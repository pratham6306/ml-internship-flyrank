Machine Learning Based Content Refresh Opportunity Scoring

FlyRank ML Internship Capstone Research

Abstract

This research presents a machine learning workflow for identifying webpages that should be prioritized for content refresh using search performance and engagement signals from the FlyRank Internship Warehouse dataset. Daily Google Search Console and Google Analytics records were aggregated into page-level features using DuckDB. A Random Forest classifier was trained on a heuristic business label representing refresh priority. The resulting model achieved very high agreement with the engineered decision rule and produced ranked recommendations for SEO teams. The proposed framework demonstrates a repeatable decision-support pipeline for large-scale content optimization.

Introduction

Modern websites often contain hundreds of thousands of pages. As content libraries continue to grow, manually identifying pages requiring updates becomes increasingly difficult. Search rankings, click-through rates, user engagement, and content freshness continuously change over time. Organizations therefore require automated methods for prioritizing which pages deserve editorial attention.

This project develops a machine learning-based content refresh recommendation system capable of analyzing aggregated website performance signals and ranking content according to its refresh priority.

Research Question

Can machine learning identify webpages that should be prioritized for content refresh using search visibility and user engagement signals?

Methodology

The workflow consisted of four major stages. First, raw daily search performance and user engagement records were loaded from the FlyRank Internship Warehouse using DuckDB. Second, page-level statistics were generated by aggregating daily observations into a single feature vector for every content page. Third, a heuristic business rule was used to identify pages that should be refreshed. Finally, a Random Forest classifier was trained to reproduce this decision process and assign refresh probabilities to every page.

Stage Description
1 Load daily warehouse data into DuckDB
2 Aggregate millions of daily records into page-level features
3 Create a refresh priority label using business rules
4 Train Random Forest and generate ranked recommendations

Feature Engineering

Daily observations were grouped by content page and client. Numerical metrics were summarized using averages, while static content attributes were preserved using their maximum value. This produced one machine learning record for every unique webpage.

Label Engineering

The FlyRank warehouse does not provide an explicit "needs refresh" target variable. Therefore, a heuristic business rule was designed to identify pages likely to require updates.

Needs Refresh =

Average Impressions > 100
AND
CTR < 2%
AND
Average Position > 15

Pages satisfying these conditions were labeled as refresh candidates. All remaining pages were treated as non-refresh examples.

Machine Learning Model

A Random Forest classifier from Scikit-learn was selected because it can model nonlinear relationships, handles heterogeneous feature scales effectively, is resistant to overfitting, and provides interpretable feature importance scores.

Experimental Results

The proposed workflow successfully transformed over 11 million daily observations into a page-level machine learning dataset containing 409,205 unique webpages. A Random Forest classifier was trained using engineered search performance and engagement features to predict refresh priority.

Metric Value
Training Samples 327,364
Testing Samples 81,841
Accuracy 99.996%
Precision 1.0000
Recall 0.9913
F1 Score 0.9956

These results indicate that the model successfully learned the heuristic decision rule used to generate refresh labels. Because the labels were engineered rather than manually annotated, the reported metrics represent agreement with the business rule instead of real-world editorial judgments.

Feature Importance

Random Forest provides feature importance values that indicate which variables contributed most to the refresh prediction. Search visibility metrics dominated the decision process, followed by engagement indicators and content characteristics.

Recommendation Engine

After model training, prediction probabilities were generated for every content page. These probabilities were interpreted as refresh priority scores, allowing webpages to be ranked from highest to lowest urgency.

Final Output
  • Refresh probability for every webpage
  • Ranked recommendation list
  • Top 1000 highest-priority pages exported to CSV

This ranking enables SEO teams to focus editorial effort on pages most likely to benefit from updates instead of reviewing thousands of pages manually.

Discussion

The proposed workflow demonstrates how search analytics and engagement metrics can be transformed into actionable recommendations through machine learning. DuckDB enabled efficient processing of millions of warehouse records while Scikit-learn provided an interpretable and scalable classification model.

The generated recommendation list can support SEO analysts, content strategists, and digital marketing teams by prioritizing webpages for optimization based on measurable performance indicators.

Limitations

  • The target label was generated using a heuristic business rule rather than human annotations.
  • The model predicts agreement with the engineered rule and not direct business impact.
  • Additional temporal features could further improve recommendation quality.
  • Future work may incorporate semantic similarity, content embeddings, and reinforcement learning for continuous optimization.

Conclusion

This project demonstrates an end-to-end machine learning workflow for identifying webpages that should be prioritized for content refresh. Starting from more than 11 million daily records, the pipeline aggregates search and engagement metrics into page-level features, engineers a business-oriented refresh label, trains a Random Forest classifier, and generates ranked recommendations. The resulting workflow is scalable, reproducible, and provides an effective decision-support tool for SEO and content optimization.

Future Work

  • Train models using human editorial feedback instead of heuristic labels.
  • Include temporal trend features over multiple time windows.
  • Incorporate semantic embeddings for content similarity analysis.
  • Evaluate gradient boosting and deep learning models for comparison.
  • Deploy the recommendation engine as a real-time dashboard.
